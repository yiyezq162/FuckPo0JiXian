# FuckPo0JiXian 运行辅助模块

（如果您不知道这个是什么，那么就不用理会）

网络变化时尝试唤起应用检查，减少漏触发。它不是保活工具：不能绕过强行停止，也不保证深度休眠时及时同步。普通用户用标准模式即可。

## 做什么

- 适用于 Magisk / KernelSU。不挂载文件，不需要 metamodule 或 SELinux 规则，也不会弹出 root 授权。
- 模块只运行一个 root `app_process` 事件 helper。国内出口查询和 Po0 请求都由 APK 自己发出；模块不保存 Token，不访问 Po0，也不读取应用状态或 SSID/BSSID。
- 网络变化时（包括同一网络上本机 IPv4 变化），3 秒内的重复事件合并为一次唤起。兜底唤起的间隔跟随应用里设置的 2–59 分钟，默认 10 分钟。每次唤起时，APK 先在本机对比出口，变化了或满一小时才查询 Po0。
- helper 另外每 60 秒检查一次自身生命周期，不发 HTTP，不持有唤醒锁。解除暂停、首次解锁、APK 更新等情况，最多触发一次恢复检查。
- 启动失败最多重试 4 次（间隔 15/30/45/60 秒），不会无限重启。

## 与 APK 的约束

- helper 只读取 APK 专用的 `runtime-v1.json`，内容是协议版本、安装随机 ID、启用状态、代次和兜底间隔。
- 通信走固定的 abstract Unix socket，只接受签名证书匹配、UID 匹配的主用户 APK；APK 也会核对对方是 UID 0。
- APK 的 versionCode 不能低于模块的 versionCode，协议版本必须一致（当前为 1）。更新 APK 不需要同时更新模块。
- 每一代 helper 都要先完成一次 APK 内的只读请求，才会允许自动写入。只完成握手不算完成。
- 只支持主用户 0，不支持工作资料或多用户。

## 诊断与停用

- 管理器里的 Action 只做一次只读诊断：检查模块目录和禁用标记、root socket 握手、查看历史报告。它不会启动 APK，也不发 HTTP。
- 在 KernelSU 上，Action 会在模块描述里写入最近一次人工检查的时间。这只是那一刻的状态，不代表模块当前在线。
- 停用：先在应用里切回标准模式，再在管理器里禁用或卸载 `fuckpo0jixian_helper`。撤销 APK 的 su 权限不起作用，因为 APK 本来就不申请 su。
- 回退不需要清除应用数据或卸载 APK，也不会删除 Po0 上的记录。

KernelSU 已有部分真机验证；Magisk 和最新修订仍需在真机上验证。
