# FuckPo0JiXian 运行辅助模块

（如果您不知道这个是什么，那么就不用理会）

在后台更及时地唤起应用检查，减少漏检。它不能绕过“强行停止”，也不保证深度休眠时能及时同步。普通用户用标准模式即可。

## 安装与更新

- 在应用「设置 → 运行模式」中选择「模块增强」，会弹出安装提示。点「安装」后，应用下载与当前 APK 同一版本的模块，按 Release 的 SHA-256 校验，然后交给 root 管理器：KernelSU 及其分支会直接打开安装界面；Magisk 会被打开，模块同时保存在「下载」文件夹，在「模块 → 从本地安装」里选择即可。安装后重启手机生效。
- 应用更新后如果模块版本较旧，「运行模式」里会出现「更新模块」，流程同上。
- `module.prop` 带有 `updateJson`，Magisk / KernelSU 也会在管理器里提示模块更新。
- APK 本身从不申请 root；安装始终由你在管理器里确认。

## 做什么

- 适用于 Magisk / KernelSU。不挂载文件，不需要 metamodule 或 SELinux 规则，也不会弹出 root 授权。模块只运行一个 root `app_process` 事件 helper。
- **底层网络**：直接监听 Wi-Fi 和移动数据本身，即使开着 VPN 也能看到底层切换。本机 IPv4 或 IPv6 前缀变化（流量重连、路由器重拨）也算网络变化。3 秒内的重复事件合并为一次唤起。
- **路由器出口**：连着 Wi-Fi 时，每 30 秒向路由器询问一次它的公网地址（NAT-PMP，或 UPnP IGD）。宽带重拨后局域网地址不变、公网 IP 变了，也能在半分钟内发现。这些查询只发往局域网里的路由器，并绑定在 Wi-Fi 上，不经过 VPN，也不访问互联网。路由器没开 UPnP / NAT-PMP 时自动停用；路由器本身在另一层 NAT 之后时（例如光猫做路由），改为每 5 分钟询问一次。
- **长时间熄屏后亮屏**：熄屏超过 10 分钟再亮屏时，触发一次本机出口比对。
- **兜底唤起**：间隔跟随应用里设置的 2–59 分钟，默认 10 分钟。每次唤起时 APK 先在本机比对出口，变了或满一小时才查询 Po0。
- **保活**：模块增强开启时，helper 每小时确认一次：把本应用加入电池优化白名单（与系统弹窗里的「允许」相同）、待机分组设为活跃、允许后台运行。只授予，不撤销。加入白名单后，深度休眠期间的模块唤起也会继续执行，而不是直接放弃。
- **时间线**：helper 在内存里保留最近 300 条事件（网络变化、路由器出口、唤起结果等），APK 读取后写入自己的运行记录，在「记录 → 导出调试信息」中可见（IP 只保留前两段）。时间线不落盘，helper 重启即清空。
- helper 每 60 秒检查一次自身生命周期，不持有唤醒锁；Handler 计时在深度睡眠时暂停，不会唤醒设备。解除暂停、首次解锁、APK 更新等情况，最多触发一次恢复检查。
- 启动失败最多重试 4 次（间隔 15/30/45/60 秒），不会无限重启。
- 国内出口查询和 Po0 请求都由 APK 自己发出；模块不保存 Token，不访问 Po0，也不读取 SSID/BSSID。

## 与 APK 的约束

- helper 只读取 APK 专用的 `runtime-v1.json`，内容是协议版本、安装随机 ID、启用状态、代次、兜底间隔和是否保活。
- 通信走固定的 abstract Unix socket，只接受签名证书匹配、UID 匹配的主用户 APK；APK 也会核对对方是 UID 0。
- APK 的 versionCode 不能低于模块的 versionCode，协议版本必须一致（当前为 1）。单独更新 APK 时模块继续工作；应用会提示把模块更新到配套版本。
- 每一代 helper 都要先完成一次 APK 内的只读请求，才会允许自动写入。只完成握手不算完成。
- 只支持主用户 0，不支持工作资料或多用户。

## 诊断与停用

- 管理器里的 Action 只做一次只读诊断：检查模块目录和禁用标记、root socket 握手、查看历史报告。它不会启动 APK，也不发 HTTP。
- 在 KernelSU 上，Action 会在模块描述里写入最近一次人工检查的时间。这只是那一刻的状态，不代表模块当前在线。
- 停用：先在应用里切回标准模式，再在管理器里禁用或卸载 `fuckpo0jixian_helper`。撤销 APK 的 su 权限不起作用，因为 APK 本来就不申请 su。模块加入的电池优化白名单不会自动撤销，可在系统的电池设置里改回。
- 回退不需要清除应用数据或卸载 APK，也不会删除 Po0 上的记录。

KernelSU 已有部分真机验证；Magisk、路由器出口监视和最新修订仍需在真机上验证。
