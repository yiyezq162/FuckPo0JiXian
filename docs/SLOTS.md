# 稳定槽位与网络授权

## 设置五槽

先检查连接，以平台实际 capacity 为准。可以把两格配置为固定网络、第三格作为本机移动、第四格注明另一台设备、第五格保留；这些名称和分配只是示例。每格编号稳定，绝不按返回列表顺序映射。空槽、保留用途和未知占用分别显示，无槽号记录独立占容量。

每槽“已核对占用，明确授权本机管理”是本地接管授权；只有你确认原写入者停止后才使用。平台不强制单写入者。只改备注不会授予写权，也不会发送请求。自动权限改变需明确确认并受全局开关与暂停控制。

固定槽先保存本机用途和占用授权，再绑定当前 Wi-Fi。绑定 SSID、AP 和当前安全类型，明确同意公网变化后更新。家庭与公司按不同身份独立跟随；在公司使用蜂窝不会冒充公司 Wi-Fi。切换已授权 Mesh AP 不需要再次确认，同名新 AP、换路由器或改 SSID 需要重新确认/绑定。绑定不是抗主动伪造 AP 的认证协议。

本机移动槽只在蜂窝或明确允许的未知 Wi-Fi 上更新；未知 Wi-Fi 默认关闭。每台手机最多一个自动移动槽。其他手机不复制本机管理权；在那台手机独立选择槽位。保留槽不自动使用，失联管理者不自动接管。

## 多设备分工

所有设备共用同一个 Token，Po0 不区分写入者，也没有备注字段，所以不做设备间通信：每台设备只授权自己负责的槽位，其余标为“其他设备”并填写设备名（如 Mac、Windows），变化时显示“其他设备已更新”，而不是“外部修改”。

- **共管固定槽**：家里的手机和电脑可同时授权同一个固定槽，并各自打开“与其他设备共管”（需重新确认授权）。对方写入非空值时本机接受为新基线，不再判为冲突；槽被清空仍按冲突处理。对方刚写入与本机出口不同的值时，本机 30 分钟内不改回（SHARED_RECENT），避免两台设备在不同网络上来回覆盖。只在同一网络的设备间开启。
- **导出 / 导入**：「设置 → 多设备 → 导出脱敏数据」移除结构化凭据、账户、Wi-Fi 与路由器身份字段，IP 字段只保留前两段。设备名、槽位备注、管理者等自由文本仍保留；手填的姓名、地址或秘密不会自动清除，分享前请检查。在另一台设备上「设置 → 多设备 → 从剪贴板导入」，只把导出方管理的槽位标为其他设备，本机管理的槽位、授权和 Po0 都不受影响。

## 现场手动固定更新

在已核对并授权的本机固定槽内选择“手动更新一次”。需要先恢复检查，可保持全局仅查询模式。现场核验出口后预览旧值 → 新值，确认只在当前账户、配置、Network 和身份观测内有效，3 分钟后失效。全局限频仍适用，界面可能等待约两分钟；返回可取消。执行前重新核验出口；离线确认不作为可重放任务。

此操作不建立长期 Wi-Fi 身份，不能绕过未知占用、出口不一致、跨槽重复或容量保护。身份权限不足时仍可使用现场手动方式；VPN 或不可信出口下仍阻止写入。

## 覆盖与归属

当前出口已在其他槽时，显示“当前出口已获覆盖，但位于槽 X，目标槽 Y 尚未更新”。没有已审核接口证据，客户端不会试探重复 CIDR 是否搬移、双占或去重；继续保留唯一 CIDR 解析约束。

把移动槽当前出口确认为固定网络不会自动搬移条目。后续移动替换可能造成该固定网络覆盖缺口。绑定确认说明远端位置和风险；用户可在移动槽单独开启“锁定当前 IP”，只暂停此槽的替换，之后自行解除。不建立永久借用关系，不自动停掉所有移动同步。

## 事务与恢复

每轮最多一个目标。全局门禁 → 恢复 pending → 固定身份 → 授权移动槽 → 观察。固定槽冲突不降级借用移动槽。完整链路是查询、授权基线检查、写前重读、出口/身份重新验证、落盘意图、定向 POST、响应核验、再次 GET 和本地提交。满额的合法原地替换允许；满额空目标不允许新增。

journal 不含凭据，绑定账户上下文、配置版本、槽位、操作、原占用、候选出口、相关身份及写前完整保护快照。落盘失败禁止 POST；写后落盘失败保留持久意图。恢复仅 GET 核对，不重放候选；旧 H2 变成 H3 时也不重放 H2。配置变化不使旧 pending 变成新授权，历史出口从不当作可覆盖基线。

单槽冲突撤销该槽有效管理权并持久隔离，其他独立合法槽继续工作。写入前读到的响应格式异常或槽位结构不符（INVALID_RESPONSE、SLOT_INVALID）只中止本次检查、按失败退避自动重试，未发出写入，不进全局保护；连续 3 次仍失败时通知。本机写入之后的核对失败、非目标丢失、账户不一致和存储异常是全局保护，进入时总会发通知。网络变化或设置改动打断检查不算失败，不触发退避。外部槽变化只更新观察，写入者仍未知。通知去重状态落盘。平台无 CAS，最后一刻竞态只能发现，不能承诺原子防止。

### 全局保护后的只读复核

概览“只读复核保护状态”在暂停时也可使用；设置“检查连接”走同一个手动只读门禁。普通自动/手动同步不能越过全局保护。复核需等待服务器限流截止，连续两次 GET 的完整结果一致并通过结构验证；不发送 POST，不提前删除 pending 或解除保护。

若待确认写入期间，非目标槽出现变化，仅接受此前已明确标为其他设备或固定共管的槽位发生非空替换。未知槽、无槽号记录、普通本机槽的变化、非目标记录丢失和容量变化仍阻止恢复，需处理实际原因后再复核，不能通过清除 journal 或忽略差异解决。复核不是写入者身份认证；两次相同读取也不是 CAS。

核对目标值为候选值时确认生效，为原值时确认未生效；其他值隔离目标槽，配置版本变化撤销目标授权。成功后才完成 journal 并解除可复核的全局保护，仍保持暂停；查看槽位和状态后显式恢复检查。恢复后按新的出口证据做新决策，不重放旧 POST。复核失败仍保留 journal 和保护。账户错配、不可读本地状态不能用复核绕过；存储恢复材料须保留。无 pending 时没有未核对的本机写入，复核与上次快照比较：同样只接受已标注的其他设备/共管槽的非空替换（其他设备照常更新自己的槽不会让本机永久卡住），其他变化仍阻止解除。

### 服务器等待与检查时间

POST 返回 429 后仍保留 pending，服务器等待截止单独持久化，不依赖 `PENDING_REVIEW`、`TOKEN_SAVED` 等显示状态。自动检查、立即检查、检查连接、只读复核、进程重建都不能提前请求 Po0；到期后 pending 仅 GET 核对。Retry-After 最长按 6 小时计，旧版本保存的更长等待在读取状态时也截到 6 小时；服务器仍要求等待时会再次返回 429。旧状态缺少独立截止字段时，对 HTTP_429/PENDING_REVIEW 保守沿用已保存的 nextAllowed。

桌面“上次检查”指 `lastCheck`，即最近一次开始 Po0 检查的时间（请求失败也可能更新），不是成功时间，也不是仅对比本机出口的时间。后台出口不变而跳过 Po0 时此时间不会刷新；出口探测的时间在记录页单独显示。

## 状态 v1 → v2

保留原文件名 state-v1.json 便于原位迁移，但 JSON version=2。首次转换前原文另存 state-v1.recovery.json，AtomicFile 提交新状态；中断可恢复，重复读取幂等。读取失败/未知版本进入恢复保护并拒绝覆盖，不用空 State 写回。

原 homeSlot/mobileSlot 编号保留。旧固定记录无 Wi-Fi 身份，homeReady=false 仍未初始化；明确重新授权后才能管理。旧移动 lastMobile/pendingMobile 先与远端核对，再继续窄化的蜂窝权限；未知 Wi-Fi 默认关闭，不无条件重放 pending。其他记录保持保护。迁移不发远端请求、不打开新增权限，保留暂停/观察模式。

更换账户、清凭据、切换演示创建新账户上下文并清理所有新槽位授权。手动确认不落盘，重启失效。重装/状态丢失不能从远端历史自动认领。旧 APK 不支持 v2，不能承诺降级读取；恢复材料也不是远端 IP 回滚能力。

Android 与桌面共用账户切换顺序：先把暂停、无授权的新账户状态落盘，再更换凭据，最后保存成功状态。第一步失败不碰凭据；后两步中断不会形成新凭据加旧授权。身份读取失败按不同账户处理。同 Token 保存保留合法配置/待核对记录并暂停，不重写相同凭据。

## Android 证据

目标 SDK 36；WifiInfo.currentSecurityType 和 FLAG_INCLUDE_LOCATION_INFO 从 API31 提供。实际请求绑定 Network，身份来自同一个默认 Network 的 transportInfo 回调；新鲜时间最长 60 秒。SSID/BSSID、权限、位置总开关及 AP 安全类型都参与验证，同一个 networkHandle 下漫游也取消旧操作。

渐进申请精确位置（同时申请 coarse/fine），不请求主动扫描或坐标，不声明 neverForLocation。附近设备权限不是 location-sensitive WifiInfo 的通用替代。仅前台权限在后台会被系统脱敏（真机已复现：后台检查返回 WIFI_UNAVAILABLE，AppOps 记录 Reject），此时安全受阻而非复用可信标记。因此固定槽的 Wi-Fi 区提供可选的“后台识别”，申请 ACCESS_BACKGROUND_LOCATION（“始终允许”）；不开启时固定槽只在应用前台识别，移动数据槽不受影响。旧 API、安全类型未知、开放网络和占位字段均不能自动固定匹配。
